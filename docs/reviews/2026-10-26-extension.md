# Directory Studio 1.6.1 插件方案与实现审查

日期：2026-10-26。基线提交：`df60cd3ecbaf009782a1eaf5d13e484004e226df`。
范围：本地未提交变更、`extension/`、共享编辑/渲染宿主接口、新版本资源、相关测试与文档。审查按迁移方案和代码审查清单逐项进行，结合实际 Chromium 验证。

## 结论

方案已实施；本轮发现的阻塞问题已修复，适合作为本地加载测试的插件候选。没有据此宣称已上架、已推送或已验证所有 Chrome/Edge 版本。

## 方案初审后的选择

- 独立 MV3 页面承载工作台。外部 file 导航自动转入，内部使用同一文档更新内容和历史；没有把原生页面上的注入速度等同于零闪烁。
- file 主机权限仅用于读取。写入要求用户显式选择文件并授予权限，绝不由一个路径自动推导写入权限。
- 依赖随包分发，编辑器使用普通打包脚本，图表使用 manifest 中声明的静态 sandbox 页面，不放宽主页面的脚本执行权限。
- 本次提供单文件写入授权；批量改名/删除、全盘扫描、系统命令、本地伴随程序均未加入范围。

## 发现并修复的主要问题

| 问题 | 失败场景 | 修复与证据 |
| --- | --- | --- |
| 外部接管遗漏同文档导航 | Studio 已打开时，再从外部打开另一个 file，浏览器只改变 hash，旧处理会恢复原路径 | 接纳没有应用状态的外部历史项；特殊字符文件路径浏览器回归通过 |
| 异步旧事件可能接管新导航 | 文件权限/存储检查等待时，用户已转到另一个地址 | 每个标签页使用最新任务标记，更新前重读当前导航；不支持的目标取消旧任务；回归测试通过 |
| 目录响应被误判失败 | Chromium 目录响应的 status=0、ok=false | 有界读取目录正文，仅解析 JSON 参数，校验每个直接子路径，绝不执行返回脚本 |
| 目录名字像文本文件 | 外部打开没有末尾斜杠的 archive.md 文件夹 | 根据实际目录响应修正分类和路径；先复现编辑器错误显示目录 HTML，再验证修复 |
| 无扩展名名字被当作后缀 | 路径名 log/py 等被错误认为文本文件 | 文件类型识别要求实际后缀；目录规范化后正常接管 |
| MV3 禁止原来的动态资源执行 | new Function 和图表 srcdoc 内联脚本不能直接迁移 | 静态编辑器脚本和独立图表页；真实 CSP 下 Mermaid 图像与交互 Markmap 均通过 |
| 保存可能错误清除新编辑 | 写入期间用户继续输入 | 仅以提交时快照更新已保存基线；新内容继续为脏状态；真实浏览器写入流回归通过 |
| 文件被外部修改或写入失败 | 保存前磁盘字节已变化、关闭写入流失败 | 比较原字节，流关闭成功后才更新状态；失败不清空编辑、不冒充成功 |
| 写入授权时机不可靠 | 读取慢或确认框停留过久后失去临时点击激活 | 紧跟文件选择请求写权限，再读字节和确认路径；有顺序回归测试 |
| 选择器不暴露绝对路径 | 通过选择器打开 Markdown，不能据文件名猜相对链接位置 | 显示「浏览器不提供绝对路径」，阻止无法定位的相对链接；显式 file URL 可继续打开 |

## 保留的边界

- 外部转入和冷启动可能出现短暂过渡，未测量或承诺零帧闪烁。内部目录和文件导航已用文档标记证明没有整页重载。
- 只支持已列出的文本/代码和浏览器可解码图片；原位保存仅支持受限大小的 UTF-8，保留 BOM 和一致的换行符。混合换行或外部修改时需保留副本并重新比较。
- 保存前比较不能提供操作系统级的跨进程事务；与其他程序同时编辑时仍需避免竞争。
- 本地目录列举使用 Chromium 的实际响应格式，未来浏览器变更需兼容调整；失败可以原生打开。
- 改权限、停用/重载扩展、浏览器强制结束可销毁页面；本版不持久化正文草稿，因此先保存。正常关闭和内部切换的脏编辑保护已验证。
- 原生打开对同一标签页和路径暂时绕过 10 分钟，防止立即重新接管。关闭标签页清理记录。
- 本地已解压安装不会获得应用商店更新，需要替换构建产物并手动重新加载。未安装到用户的日常浏览器，未改系统文件关联。
