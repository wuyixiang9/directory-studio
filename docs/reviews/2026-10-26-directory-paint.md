# 插件 1.6.2：目录切换闪动修复

用户反馈：周围工作台容器已较稳定，但目录区域仍会闪动。

## 根因与复现

插件 1.6.1 在每次 renderTarget 开始时立即显示 #loading；该元素用绝对定位铺满内容区，并绘制不透明背景。目录本身虽未被提前清空，仍被这层背景遮盖，读取结束又撤去，造成列表的闪动。

先增加浏览器回归：只延迟真实目录 fetch 的返回，不替换数据；跨两个绘制帧检查原条目仍在 DOM 中，且 elementFromPoint 命中原条目。用保留的 1.6.1 安装目录运行时，测试因遮罩挡住原条目而失败。记录在交付验证日志 directory-before.log。

## 修复

- 保留已经绘制的目录和滚动位置，继续读取真实数据；新结果准备好后在同一任务里更新列表。
- 删除整块背景遮罩，将读取提示放进固定高度的底部状态栏，读取超过 180 毫秒才显示。没有增加淡入淡出或重绘整个工作台的动画。
- 用 aria-busy 表示内容区正在读取；提示不挡住列表，可以在等待时点击其他目录。
- 新导航清理旧提示计时器；较早的请求被取消或失效后，不得更新页面、清除新任务的忙碌状态或重新显示旧提示。
- 失败保留原条目，清理忙碌状态和提示。沿用原来的未保存内容保护与文件访问边界。
- 插件候选递增到 1.6.2，构建校验改为独立读取插件 manifest 版本；油猴版保持 1.6.1。本次没有重建或改动油猴资源。

## 审查与验证

审查范围：extension/studio.js、studio.html、studio.css、manifest、版本校验及新增浏览器回归。

- 真实 Windows Chromium 151.0.7922.34 加载交付的 Directory-Studio-1.6.2 目录：27 个场景通过，页面错误为 0，测试中的 HTTP/HTTPS 请求为 0。
- 新增的 3 个场景：延迟读取时旧条目跨绘制帧仍可见且未被遮挡；前一个读取尚未结束时可选择新目录且旧结果不能覆盖它；读取失败保留相同的原条目节点，提示计时器不在之后重新冒出。
- 原有外部 file 接管、冷启动、目录分类、排序/过滤/分页、图表、图片、编辑保护与文件保存场景继续通过。
- 完整 Node 回归结果见 validation/1.6.2/unit-tests.log；最终构建及打包文件也按交付清单检查。

没有发现本轮变更的未修复阻塞项。本修复消除的是工作台主动遮盖目录引起的闪动，不承诺浏览器首次打开、外部转入及新目录内容本身变化时绝对无视觉变化。
